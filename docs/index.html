One target in, a native app out — without shipping a runtime

macOS · Windows · Linux · iOS · Android byte-exact URLs a folder origin that survives restarts no Node inside the app any framework, one contract unknown stays unknown

Shipping a web app as a native app usually means shipping a runtime with it: a Node sidecar, a bundled static-site generator or a dev server the wrapper starts and stops for you. defuss-tauri takes the one thing your toolchain already produces — a running URL or a built folder — generates a small Rust host and runs a pinned Tauri CLI on it. Your framework, your toolchain and your server stay exactly as they are; defuss-tauri owns only the wrapper.

Byte-exact URLs

The URL opens exactly as given, including path, query and fragment, and packaging never contacts the service.

A folder origin that survives restarts

The folder is served from 127.0.0.1 on a port chosen once and kept, so the app's storage survives; release builds embed the selected files once.

Nothing extra ships

Secrets, VCS data, dependency trees and hidden files are excluded, .well-known is kept, and every symlink is rejected.

Hash-owned host files

A generated file you edited is refused, never overwritten. Signing and other changes in Tauri's gen/ directory survive every run.

No lifecycle

The CLI never installs the target's dependencies, starts or stops its server, scans its port or requires it to be online during packaging.

Unknown stays unknown

Certificate errors are never bypassed — self-signed dev servers load through a CA installed on the OS or device — and platforms without a real run are reported as open, never claimed.

How it works

🖥️ From one target to a native app

You bring one target — a URL your toolchain serves or a folder it built. The CLI validates, selects and generates; a pinned Tauri CLI compiles and bundles; the generated Rust host opens the URL byte for byte or serves the folder from a 127.0.0.1 listener whose port is chosen once and kept. The CLI only ever reads the target.

Scroll the diagram sideways to see the whole pipeline.

What the CLI actually does

It takes the one thing your toolchain already produces — a running URL or a built folder — generates a small Rust host and runs a pinned Tauri CLI on it. It never builds, installs, starts or stops your application, so any framework works as long as it produces a URL or a folder.

Validation runs first, so Tauri's own installers never run: what is missing is listed, not installed. Only src/tooling.ts may spawn build processes. --dry-run reads and validates only — no writes, commands or network — and --prepare-only generates the Rust host without any toolchain.

bun install
make example-static ARGS=--prepare-only
Prepared /examples/static; 2 selected assets (1306 bytes). Host: /tmp/examples/static/managed/dev/src-tauri
make example-static compiles that host and opens the example in a native window
the first run also installs the pinned Tauri CLI into the managed directory
Stages

🧭 Who drives what

Four drivers, one boundary each: your toolchain produces the target, the CLI validates, selects and generates, a pinned Tauri CLI builds, and the generated Rust host runs inside the app.

Your toolchain

Produces the URL or the folder. The CLI only ever reads it.

The CLI

Validates, selects and generates. Only src/tooling.ts may spawn build processes, and nothing writes silently.

A pinned Tauri CLI

Installed into the managed directory, never globally. Compiles and bundles the host.

The Rust host

Opens a URL byte for byte, or serves the selected files from a 127.0.0.1 listener. Executes no application or backend code; the platform WebView runs your frontend.

The contract

🤝 Your app stays yours

defuss-tauri does not ship a one-size-fits-all scaffold. It enforces a small contract, and any project that already meets it works unchanged. Each card names the rule and why it beats the plausible alternative.

Any framework, one contract

Your toolchain produces a running URL or a folder of files; everything before that point is yours. Why: a wrapper that understood frameworks would age with every one of them.

No lifecycle representation

The CLI never installs the target's dependencies, spawns its server, sends it shutdown signals, scans or rewrites its port, or requires it to be online during packaging. Why: a process the CLI cannot observe cannot be managed, only corrupted.

Selection, not staging

Assets are chosen by exact path prefixes, secret and VCS exclusions always win, and .well-known is preserved. Why: whole-project staging ships your node_modules, your build cache and, eventually, a secret.

Generated files are hash-owned

Edit one and the CLI refuses to run instead of deleting your customization; signing and other changes in Tauri's gen/ directory survive every run. Why: a generator that silently overwrites teaches you never to touch its output, which breaks the moment you must.

Unknown stays UNKNOWN

Certificate errors are never bypassed and no trust store is edited — self-signed HTTPS means a CA you install — and secure-context and service-worker claims come only from probes in the real embedded WebView, never from Chromium or Safari, with unproven platforms staying open. Why: a support claim without evidence is worse than none. The open work is listed in docs/NATIVE_GATES.md (opens in a new tab).

Bring your own Rust — opt-in

rust.extensions points the host at crates you own: their defuss_tauri_extend wraps the Tauri builder first, and capability objects ship as data. Why opt-in: the default host stays wrapper-only — no IPC surface you didn't write yourself — and your native code gets the review a native change deserves. Try it: make example-rust-extension adds a custom Rust menu.

Usage

⌨️ dev, build, init and doctor

The examples run the published package with bunx defuss-tauri; from a checkout the same interface is node dist/cli.js after make setup has built dist/. Without a command the CLI runs dev; without a target it uses ./defuss-tauri.json, else the current directory.

Dev: wrap a running server or a folder

Start the service behind a URL yourself; defuss-tauri never supervises it.

  • In desktop dev, edits to existing files show up on reload; new files need a restart.
  • The native menu's Reload configured target (Cmd/Ctrl+R) reloads.
  • https://user:password@host is rejected; log in through the service instead.
bunx defuss-tauri dev http://127.0.0.1:5173
bunx defuss-tauri dev ./public

Build: package the target

Release builds embed the selected files once; --config picks a configuration file.

  • Desktop targets must match the build machine.
  • Folder assets are selected by prefix, never staged wholesale.
  • --dry-run reads and validates only: no writes, commands or network.
bunx defuss-tauri build ./dist
bunx defuss-tauri build --config app/defuss-tauri.json

Mobile: iOS and Android

The CLI never installs SDKs, Homebrew packages or Rust targets; it checks them first so Tauri's own installers never run.

  • make setup-ios and make setup-android install them on request and end with doctor, which fails while anything is missing.
  • Folder targets embed their files even in dev, because a phone cannot read this disk; restart dev after changing files.
  • Android dev runs adb reverse, so start the emulator or connect the device first.
bunx defuss-tauri doctor --platform ios
bunx defuss-tauri dev --platform ios
bunx defuss-tauri build --platform android

Init and doctor

init writes a configuration file; doctor reports toolchain and configuration findings and lists exactly what is missing.

  • Removed flags of the old package (--host, --skip-ssg, --node-version and others) fail with a migration hint.
  • defuss-tauri.schema.json gives editors completion for the file.
bunx defuss-tauri init --app-name "My App"
bunx defuss-tauri doctor

Proven on macOS, open everywhere else*

On macOS 15.7 (arm64) this is proven, not promised: make native-test, make mobile-check and make native-probe pass, and the real embedded WKWebView — the same WebKit your shipped app runs on — served the folder target as a secure context on 127.0.0.1, with a service worker that activates, controls the page and intercepts every fetch, and localStorage, CacheStorage and IndexedDB that survive a full restart. The boundary is just as honest: each layer below proves exactly its own scope, Windows, Linux, iOS and Android are still open, and anything without evidence stays UNKNOWN — never dressed up as working. docs/NATIVE_GATES.md (opens in a new tab) tracks the open native work.

macOSruns the folder-loopback scope end to end in the real WKWebView: secure context, service worker activation, control and interception, storage that survives a restart
6scopes with direct evidence in this repository's fast gates, from make test to make native-probe — CLI, tarball, sockets, mobile cross-compile and the WebView probe
27platform, profile and scope reports the release gate demands; only the folder-loopback scope has a runner so far
0production npm dependencies; the native app never acquires Node, Bun or npm
URL targets HTTPS with an installed self-signed CA: no verified run yet upgrade and distribution scopes Windows · Linux · iOS · Android runs

* Each layer proves only its own scope. Toolchain observations from 2026-10-05: Node 24.14, rustc 1.96, macOS 15.7 (arm64). make release-gate is the certification boundary.

Quick start

🚀 Up and running in a minute

Requirements: Node ≥ 20.19 for the CLI. Bun installs the development dependencies (make setup installs Bun if it is missing); dev and build also need Rust and Tauri's OS prerequisites. Generated apps need macOS 14 or iOS 17 or later.

From a checkout

Prepares the example's Rust host without any toolchain; make example-static then compiles it and opens the example in a native window.

  • The first run also installs the pinned Tauri CLI into the managed directory, which takes a few minutes.
  • Generated hosts go to the ignored tmp/, never into examples/.
  • make example-rust-extension opens the custom-Rust example instead: a native menu from your own crate.
bun install
make example-static ARGS=--prepare-only
Prepared /examples/static; 2 selected assets (1306 bytes). Host: /tmp/examples/static/managed/dev/src-tauri
make example-static opens the example in a native window

Published package

Wrap a URL your toolchain already serves, or a folder it built. Start the service behind a URL yourself; defuss-tauri never supervises it.

  • Without a command the CLI runs dev; without a target it uses ./defuss-tauri.json, else the current directory.
  • init writes the configuration file for you.
bunx defuss-tauri dev http://127.0.0.1:5173
bunx defuss-tauri dev ./public
bunx defuss-tauri build ./dist
